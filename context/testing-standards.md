# Testing Standards

## Общие принципы

### Behavior over Implementation
**ДОЛЖНО**: Тестировать наблюдаемое поведение (observable behavior) — то, что видит пользователь.
**ЗАПРЕЩЕНО**: Тестировать внутренние детали реализации (состояние, приватные методы, `useState`, внутренние переменные).

### One Scenario Per Test
Каждый тест проверяет ОДНО поведение. Название теста описывает наблюдаемый результат.

### No Duplication
Не дублировать тесты. Если интеграционный/UI тест уже покрывает поведение, unit-тест на внутренние функции **не нужен**, кроме случаев:
- Функция содержит критичную бизнес-логику (расчёты, сложная валидация)
- Функция используется в нескольких местах — для надёжности и скорости обратной связи

### AAA Pattern
Все тесты следуют структуре:

1. **Arrange** — подготовка входных данных и зависимостей
2. **Act** — вызов тестируемого кода / симуляция действия
3. **Assert** — проверка наблюдаемого результата

### Mocking Principles
- Мокать **только** внешние зависимости (API, БД, файловая система, аналитика)
- **НЕ** мокать внутренние функции внутри тестируемого модуля
- Мокать **только** то, что мешает тесту, а не всё подряд

### Test Types by Target

| Тип цели | Тип теста | Что проверяет |
|----------|-----------|---------------|
| UI компонент | Behavior test | Пользовательские взаимодействия и результат в DOM |
| Pure logic | Unit test | Вход → Выход, ветвления, edge cases |
| Hook / Custom function | Hook behavior test | Возвращаемые значения и побочные эффекты |
| API / External service | Integration test | Взаимодействие с внешними системами (через моки) |
| Repository / DAO | Integration test | Чтение/запись, транзакции, маппинг |

### Quality Checklist (минимальный)

- [ ] Тест не обращается к внутренностям (хукам, переменным, состоянию)
- [ ] Используются семантические запросы / значимые ассерты
- [ ] Один тест — один сценарий
- [ ] Название описывает **ожидаемое поведение**
- [ ] Нет лишних моков

### Forbidden Patterns

| Паттерн | Почему плох |
|---------|-------------|
| `expect(component.state).toBe(...)` | Тестирование внутреннего состояния |
| `jest.mock(internalFn)` | Мокание внутренней логики |
| `expect(wrapper.instance().method)` | Тестирование реализации, а не поведения |
| `toMatchSnapshot()` как единственная проверка | Нет проверки поведения |
| `act(() => ...)` без `await` (UI) | Устаревший паттерн, race condition |
