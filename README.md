# gigatest

`gigatest` — это расширение для структурированного тестирования в Qwen Code. Цель — предоставить дисциплинированный workflow для аудита, написания, ревью и верификации тестов, применимый к UI (React) и Backend (Java) стекам через систему оверлеев.

## Основные принципы

- `skills-first` workflow для audit, implementation, review и verification
- сфокусированные субагенты для каждого этапа тестирования
- итеративное выполнение: одна задача за итерацию с `agent-state.json`
- stack-agnostic core с React- и Java-оверлеями для специфичных стратегий

## Зачем Нужно Это Расширение

Это расширение предназначено для команд и разработчиков, которым нужен системный подход к тестированию. Вместо хаотичного написания тестов `gigatest` предоставляет:

1. **Аудит** — объективную оценку покрытия и качества существующих тестов
2. **Приоритизированный план** — что тестировать первым, основываясь на риске и бизнес-ценности
3. **Итеративное выполнение** — по одной задаче за раз, с синхронизацией состояния
4. **Контроль качества** — ревью тестов на соответствие стандартам перед мержем
5. **Верификацию** — обязательный прогон тестов перед объявлением готовности

## Установка

### Подключение из локального checkout

```bash
qwen extensions link %{gigatest}
```

### Установка из git-репозитория

```bash
qwen extensions install <git-url>
```

### Просмотр установленных расширений

```bash
qwen extensions list
```

## Workflow По Умолчанию

Для задач тестирования используйте `skills-first` путь:

1. `using-gigatest` маршрутизирует в правильный workflow stage
2. `test-audit` — полный аудит покрытия и качества тестов
3. `test-implementation` — итеративное создание/доработка тестов
4. `test-review` — ревью качества написанных тестов
5. `test-verification` — прогон и проверка тестов перед завершением

## Ручные Fallback-Команды

Slash-команды доступны для явного контроля:

1. `/audit-tests` — запустить аудит существующих тестов
2. `/implement-tests` — выполнить следующую задачу из плана
3. `/review-tests` — ревью качества существующих тестов
4. `/run-tests` — запустить и проверить тесты

## Структура Репозитория

```text
.
├── qwen-extension.json
├── QWEN.md
├── README.md
├── agents/
├── commands/
├── skills/
├── context/
└── plans/
```

### Основные директории

- `skills/`: workflow-политика для audit, implementation, review и verification
- `agents/`: ролевые промпты для `test-auditor`, `test-implementer`, `test-reviewer`, `test-strategist`
- `commands/`: ручные точки входа для поэтапного управления
- `context/`: базовые стандарты тестирования и stack-specific оверлеи
- `plans/`: примеры артефактов, создаваемых workflow

## Stack-Neutral Core по Умолчанию

Расширение придерживается stack-neutral позиции. React- и Java-specific рекомендации доступны как оверлеи, встроенные в `context/`. Это делает расширение полезным для mixed-stack кодовых баз.
