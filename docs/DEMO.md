# DEMO.md — Сценарий демонстрации GigaTest за 15 минут

> Версия: 1.0 | Дата: 2026-04-18
>
> **Назначение:** Пошаговый сценарий живой демонстрации GigaTest от аудита до верификации.
> **Аудитория:** Разработчики, техлиды, менеджеры — все, кто хочет понять ценность GigaTest за 15 минут.
>
> **Предварительные условия:**
> - Qwen Code с установленным расширением `gigatest-0.1.0`
> - Учебный проект `counter-app` (или любой React/JS/Java проект с кодом без тестов)
> - Базовое понимание что такое «тесты»

---

## Тайминг

| Этап | Время | Что показываем |
|------|-------|----------------|
| 1. Ввод | 1 мин | Проблема и решение |
| 2. Аудит | 3 мин | `/audit-tests` → `agent-state.json` |
| 3. Стратегия | 2 мин | Приоритизация и план |
| 4. Имплементация | 4 мин | Пошаговая реализация |
| 5. Ревью | 2 мин | Качество тестов |
| 6. Верификация | 2 мин | Запуск и подтверждение |
| 7. Итог | 1 мин | Результат и следующие шаги |

---

## Сценарий 1: «Нет тестов совсем» (рекомендуемый)

**Учебный проект:** `counter-app` — простое React-приложение с компонентом Counter, хуком useCounter и утилитой formatCounter.
**Код:** 3 файла, ~150 строк. Тестов нет.

### Шаг 1: Ввод (1 минута)

```
ДЕМОНСТРАТОР:
«Сегодня покажу GigaTest — skills-first тестовый workflow для AI-агентов.
Сценарий: у нас есть код, но нет тестов.
За 15 минут пройдём полный цикл: audit → strategy → implement → review → verify.»

[Открыть проект counter-app в Qwen Code]
[Показать 3 файла без тестов]
«Вот проект. Три файла. Ноль тестов. Запускаем /audit-tests.»
```

### Шаг 2: Аудит (3 минуты)

```
[Выполнить: /audit-tests]

ДЕМОНСТРАТОР:
«Агент test-auditor загружает skill test-audit и начинает анализ.
Он не пишет тесты — он находит что уже покрыто, а что нет.»

[Показать создание файлов:]
  .gigacode/plans/tests-audit-2026-04-18/agent-state.json
  .gigacode/plans/tests-audit-2026-04-18/test-plan.md

«Вот agent-state.json — машиночитаемый источник истины.
А вот test-plan.md — человекочитаемый отчёт, сгенерированный из JSON.
Double documentation — каждое изменение state автоматически отражается в Markdown.»

[Открыть test-plan.md]
«Видим: 3 target-файла, coverage = missing.
Аудитор нашёл 0 тестов и создал план.»
```

### Шаг 3: Стратегия (2 минуты)

```
ДЕМОНСТРАТОР:
«Аудит показал: тестов нет. Теперь test-strategist строит план.
Он определяет какие тесты нужны, в каком порядке, с какими quality gates.»

[Показать agent-state.json → раздел plan.items]
«Смотрим план:
  AUDIT-001: audit (done) ✓
  STRATEGY-001: стратегия (done) ✓
  IMPL-001: Counter UI behavior tests — CRITICAL
  IMPL-002: useCounter hook tests — HIGH
  IMPL-003: formatCounter unit tests — MEDIUM
  REVIEW-001: review качества тестов
  VERIFY-001: verify что тесты проходят

Приоритизация: сначала критичные user-facing тесты, потом хуки, потом утилиты.
Каждая задача имеет quality_gate — явные критерии готовности.»
```

### Шаг 4: Имплементация (4 минуты)

```
ДЕМОНСТРАТОР:
«Теперь test-implementer реализует тесты — по одной задаче за итерацию.
Это ключевое отличие GigaTest: атомарные итерации, никогда не теряем прогресс.»

[Выполнить: /implement-tests]

[Показать IMPL-001 — Counter UI tests]
«Первая итерация: behavior tests для Counter component.
userEvent.click, проверка обновления DOM, disabled state.
Не мокаем React internals — тестируем поведение.»

[Показать создание src/components/__tests__/Counter.test.tsx]
«Файл создан. State обновился: IMPL-001 → done, coverage → partial.
test-plan.md регенерирован автоматически.»

[Показать IMPL-002 — useCounter hook tests]
«Вторая итерация: hook tests через renderHook + act().
Начальное состояние, increment, decrement, reset.»

[Показать IMPL-003 — formatCounter unit tests]
«Третья итерация: чистая функция, просто input → output.
Положительные, отрицательные, ноль, большие числа с локалью.»

[Показать agent-state.json checkpoint после каждой итерации]
«Обратите внимание: после каждой итерации agent-state.json содержит checkpoint.
Если агент прервётся — он продолжит с этого места. Никакой потери контекста.»
```

### Шаг 5: Ревью (2 минуты)

```
ДЕМОНСТРАТОР:
«Тесты написаны. Но хороши ли они? test-reviewer проверяет качество.»

[Выполнить: /review-tests или агент автоматически запускает review]

[Показать review-summary.md]
«Review проверяет:
  ✓ Behavior-first подход (не тестируем implementation details)
  ✓ AAA pattern (Arrange-Act-Assert)
  ✓ Нет excessive mocking
  ✓ Нет доступа к внутреннему состоянию

Результат: passed. Минорное замечание — добавить тест на rapid consecutive clicks.
Это можно сделать в следующей итерации.»
```

### Шаг 6: Верификация (2 минуты)

```
ДЕМОНСТРАТОР:
«Финальный шаг — test-verifier запускает тесты и подтверждает что они проходят.»

[Выполнить: npm test или /run-tests]

[Показать вывод]
«9 тестов проходят. Exit code 0.
Покрытие: Counter 87%, useCounter 92%, formatCounter 100%.»

[Показать agent-state.json → VERIFY-001: done]
[Показать test-plan.md → прогресс 100%]
«State обновился: VERIFY-001 → done, progress → 100%.
Workflow завершён. Все стадии прошли.»
```

### Шаг 7: Итог (1 минута)

```
[Показать summary]
«Итого за одну сессию:
  3 целевых файла → 9 тестов → покрытие 87%+
  7 задач, 5 стадий, ноль эскалаций к человеку

Что мы получили:
  ✅ agent-state.json — полный checkpoint, можно продолжить позже
  ✅ test-plan.md — наглядный отчёт для PR
  ✅ 3 тестовых файла с passing tests
  ✅ review-summary.md — подтверждение качества тестов

GigaTest — это не "напиши тесты". Это управляемый, воспроизводимый,
верифицируемый процесс тестирования с AI-агентом.»
```

## Сценарий 2: «Есть плохие тесты»

**Время:** ~12 минут (пропускаем стратегию, начинается с аудита качества)

### Отличия от Сценария 1

| Шаг | Отличие |
|-----|---------|
| 1. Ввод | Показать существующие тесты — snapshot-only, тестируют implementation |
| 2. Аудит | Аудитор находит invalid_coverage → качество тестов низкое |
| 3–4. Имплементация | Replace bad tests → behavior-first, AAA pattern |
| 5. Ревью | Reviewer подтвердит что новые тесты лучше |
| 6. Верификация | Без изменений (все тесты проходят) |

### Ключевые моменты для демонстрации

```
[Показать «плохой» тест]
«Смотрим: это snapshot-тест. Он проверяет что компонент "выглядит так же".
Но если поведение изменится — snapshot пройдёт. Это не тест поведения.»

[Показать audit с invalid_coverage]
«Аудитор видит: тесты есть, но coverage = invalid.
Они не проверяют поведение.»

[После имплементации]
«Новый тест: userEvent.click → проверка что число изменилось.
Это test behavior. Если логика сломается — тест упадёт.»
```

## Что делать если что-то пошло не так

### Тесты не проходят на VERIFY

```
ДЕМОНСТРАТОР:
«Тесты не прошли. Это нормально — для того и верификация.
Агент вернётся к IMPL, исправит, и запустит VERIFY снова.
State сохранится — прогресс не потеряется.»
```

### Ревью не прошло

```
ДЕМОНСТРАТОР:
«Review вернул задачи на доработку.
test-implementer исправит quality gate violations.
Следующая итерация ревью подтвердит исправления.»
```

### Агент прервался mid-session

```
ДЕМОНСТРАТОР:
«Агент остановился на IMPL-002. Открываем agent-state.json.
Видим checkpoint: iteration 4, IMPL-002 → done.
Перезапускаем имплементацию — агент продолжает с IMPL-003.
Никакой потери контекста.»
```

## Файлы-артефакты демо

После полного цикла демонстрации существуют:

| Файл | Описание | Роль в демо |
|------|----------|-------------|
| `agent-state.json` | Машиночитаемый источник истины | Показываем checkpoint, history, artifacts |
| `test-plan.md` | Человекочитаемый отчёт | Показываем прогресс и покрытие |
| `src/__tests__/*.test.*` | Реальные тестовые файлы | Показываем результат работы |
| `review-summary.md` | Отчёт ревьюера | Показываем quality gate |
| `test-run-output.txt` | Вывод test runner | Показываем verification |

## Чек-лист готовности демо

- [ ] Учебный проект `counter-app` существует и запускается
- [ ] В проекте нет тестов (или есть intentionally bad tests для сценария 2)
- [ ] GigaTest extension установлен и активен
- [ ] Все команды (`/audit-tests`, `/implement-tests`, `/review-tests`) работают
- [ ] `agent-state.json` валидируется через `tools/validate-state.js`
- [ ] `test-plan.md` генерируется через `tools/generate-report.js`
- [ ] Тайминг каждого этапа укладывается в план
- [ ] Демонстратор прошел весь сценарий хотя бы раз без зрителя
