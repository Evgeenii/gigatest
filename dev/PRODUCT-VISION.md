# GigaTest — Видение продукта

> Версия: 2.0 | Дата: 2026-05-04
> Позиционирование продукта, целевая аудитория и стратегические цели.

---

## 1. Формулировка продукта

**GigaTest** — это skills-first расширение для структурированного тестирования в Qwen Code. Заменяет хаотичное написание тестов структурированным, управляемым конечным автоматом процессом от аудита до мержа.

### Проблема

Написание тестов с AI-агентами — хаотично:
- Агенты пишут тесты вслепую, не понимая существующего покрытия
- Нет приоритизированного плана → дубликаты, пробелы, низкоценные тесты
- Нет контроля качества → тесты, которые мокают внутренности, тестируют реализацию, не учитывают async
- Потеря контекста между сессиями → работа повторяется с нуля
- Нет верификационных ворот → тесты коммитятся без доказательства, что они проходят

### Решение

GigaTest обеспечивает дисциплинированный рабочий процесс:

```
Аудит → План → Реализация (итер.) → Ревью → Верификация → Готово
```

Каждая стадия — **навык** со строгими условиями выхода. Состояние переживает сессии через два git-трекаемых файла.

## 2. Целевая аудитория

| Сегмент | Потребность | Как GigaTest решает |
|---------|-------------|---------------------|
| **Тимлиды** | Поддерживать качество тестов в командах | Аудит ловит пробелы до их роста; ревью обеспечивает качество |
| **Разработчики** | Писать тесты быстрее и увереннее | Агент берёт на себя написание; стандарты обеспечивают корректность |
| **Архитекторы** | Понимать архитектуры тестирования | Навык стратегии декомпозирует область до реализации |
| **QA-инженеры** | Видимость покрытия | План показывает точно: что покрыто, что — нет |
| **Open source мейнтейнеры** | Согласованный стиль | Обнаружение конвенций изучает существующие паттерны |

## 3. Ключевые отличия

### 3.1 Skills-first архитектура

В отличие от agent-first инструментов, пользователи **описывают задачи естественным языком**. Навык-маршрутизатор анализирует интент и направляет в нужную стадию процесса. Навыки — публичный интерфейс; агенты — деталь реализации.

### 3.2 Конечный автомат с git-видимостью

Каждый план создаёт два файла:
- `agent-state.json` — валидируется по JSON Schema, машиночитаемый
- `test-plan.md` — человеко-читаемое зеркало, git-diff friendly

Оба файла **можно закоммитить в репозиторий**. PR показывает, что планировалось vs. что доставлено.

### 3.3 Ворота качества (Q1–Q9)

Каждый тест оценивается по 9-элементному чеклисту, который обеспечивает:
- **Тестирование поведения** (а не деталей реализации)
- **Отсутствие излишних моков**
- **Корректность async**
- **Покрытие веток**

Трёхуровневая система (required/recommended/optional) даёт нюансированный скоринг.

### 3.4 Персистентность сессий

Агенты теряют контекст между сессиями. GigaTest решает это через `agent-state.json` — полную историю выполнения, память и план. Новая сессия загружает файл и **продолжает с checkpoint**, а не с нуля.

### 3.5 Обнаружение конвенций

Вместо навязывания стиля, GigaTest **учится** конвенциям тестирования проекта:
- Сканирует существующие тестовые файлы
- Читает конфиги (jest.config, pom.xml, build.gradle)
- Извлекает документацию команды (CONTRIBUTING.md)
- Выводит `project-conventions.json` → после ревью все агенты следуют ему

## 4. Поддерживаемые стеки

| Стек | Оверлей | Статус |
|------|---------|--------|
| React + RTL | react-testing.md | Продакшн-готовый |
| Java + Spring Boot | java-testing.md | Продакшн-готовый |

React покрывает тестирование фронтенда/UI (крупнейший кейс). Java покрывает бэкенд/API-тестирование (enterprise-кейс). Вместе они покрывают ~80% потребностей типичного веб-приложения.

GigaTest stack-agnostic по дизайну — если проект не определён в списке, используется `testing-standards.md` как fallback. Команда может определить собственные конвенции через `convention-discovery`.

## 6. Стратегические цели на следующий цикл

### 6.1 Директория dev/ как источник истины для агентов

- Любой агент, подключающийся к сессии разработки, читает `dev/` для контекста
- Люди-разработчики используют те же файлы для понимания проекта

### 6.2 Богатые примеры

Добавить реалистичные примеры планов:
- React + Java мультистек-пример аудита
- Пример реализации на React
- Пример стратегии на Java
- Пример обнаружения конвенций

---

## 7. Не цели (Non-Goals)

GigaTest **НЕ**:
- Запускает тесты в CI/CD пайплайнах (генерирует планы, которые CI может верифицировать)
- Заменяет человеческое код-ревью (дополняет воротами качества)
- Генерирует продакшн-код (только тесты, W0.4 обратимость)
- Поддерживает каждый тестовый фреймворк (фокус на React + Java)
- Работает как standalone CLI (требует экосистему Qwen Code)
